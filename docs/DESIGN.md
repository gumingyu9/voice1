# Voice Lab — 목소리 구성 요소 실험실 설계서 (v0.1)

> 목적: 목소리를 결정하는 요소들을 **설정값(파라미터)** 으로 쪼개고, 각 값이 **사람 몸의 어디**에 해당하는지 그림과 설명으로 보여주며, 입력한 단어를 그 설정으로 **직접 들어볼 수 있는** 로컬 웹 앱.

---

## 1. 핵심 아이디어: 음원–필터 모델

사람의 목소리는 크게 세 단계로 만들어진다. 앱 전체 구조(UI 구획, 파라미터 분류, 그림)를 이 세 단계에 맞춘다.

```
 [1. 동력]            [2. 음원 Source]           [3. 필터 Filter]            [4. 조음·말투]
  폐·횡격막   ──공기──▶  후두·성대 진동   ──버즈음──▶  성도(목·입·코) 공명  ──▶  혀·입술·턱의 움직임, 속도, 억양
  "얼마나 세게"         "음높이·음질"               "음색·체격감"               "무슨 말을, 어떤 말투로"
       │                     │                          │                           │
   음량, 호흡 길이       F0, 기식음, 거칠기,        성도 길이, 비음, 밝기,       말 속도, 억양 폭,
                         떨림, 보컬 프라이          명료도, 공명 링               자음 세기, 치찰음
```

- **음원(성대)** 은 "주기적인 버즈음 + 숨소리 잡음"을 만든다 → 스펙트럼에서 *배음(줄무늬)* 으로 보임.
- **필터(성도)** 는 그 버즈음 중 특정 주파수대(포먼트)를 강조한다 → 스펙트럼의 *봉우리 모양* 으로 보임.
- 이 둘을 **화면에서 분리해서 보여주는 것**(음원 스펙트럼 × 필터 곡선 = 최종 스펙트럼)이 이 앱의 가장 중요한 교육 장치다.

## 2. 합성 엔진 전략 (가장 중요한 결정)

"요소를 이해하기 쉬움"과 "실제 사람처럼 들림"은 서로 충돌한다. 그래서 **두 엔진을 같은 파라미터 체계로** 운용한다.

| | 엔진 A: 해부학 엔진 (포먼트 합성) | 엔진 B: 자연음 엔진 (TTS + 보코더 변형) |
|---|---|---|
| 방식 | Klatt 방식 음원–필터 합성기. 성대 펄스(LF 모델) → 공명기 직렬/병렬 | 로컬 신경망 TTS로 기본 음성 생성 → WORLD 보코더로 분해(F0 / 스펙트럼 포락 / 비주기성) → 파라미터대로 변형 후 재합성 |
| 실행 위치 | 브라우저 (AudioWorklet, 서버 불필요) | 로컬 Python 서버 (FastAPI) |
| 투명성 | 모든 파라미터가 물리 요소와 1:1 대응 | 대부분 대응 (일부는 근사) |
| 음질 | 기계적·로봇 같은 소리 | 자연스러움 (극단값에서 왜곡) |
| 실시간 | 슬라이더를 움직이는 즉시 소리 변화 | 재생 버튼 → 0.5~2초 후 재생 |
| 역할 | **"원리를 귀로 확인"** | **"실제 사람 목소리로 확인"** |

- 같은 슬라이더 상태로 A/B 엔진을 토글하며 비교할 수 있게 한다.
- 엔진 A만으로도 앱이 완결되도록 먼저 만들고(P1~P2), 엔진 B는 이후 단계(P3)에서 붙인다.

### 2.1 "거의 모든 목소리" 범위에 대한 정직한 정의
- 목표: **목소리 유형의 공간**(나이, 성별 특성, 체격, 발성 습관, 쉰 목소리·콧소리·속삭임 같은 상태, 말투)을 연속적으로 덮는 것.
- 비목표: 특정 개인을 똑같이 복제하는 것(보이스 클로닝). 개인 고유성은 미세한 스펙트럼 특징·억양 습관·방언까지 얽혀 있어 슬라이더 몇 개로 완전히 재현되지 않는다. 이 한계 자체도 앱에서 "목소리의 고유성"이라는 설명 카드로 다룬다.
- 향후 확장(P4): 내 목소리를 녹음 → 분석해서 슬라이더 값을 자동 추정 → "내 목소리는 이런 요소로 이루어져 있다"를 보여주는 기능.

## 3. 파라미터 체계

### 3.1 설계 원칙
1. **단일 정의 파일**(`params/schema.ts`)이 모든 것의 원천: 슬라이더 UI, 설명 카드, 그림 연결, 엔진 매핑이 전부 여기서 생성된다.
2. 모든 파라미터는 **신체 요소 → 음향 변화 → 들리는 느낌 → 실생활 예시** 4가지 설명을 가진다.
3. 사람이 이해하는 단위 사용 (Hz, cm, %, 음절/초). 내부 엔진 값은 매핑 함수로 변환.
4. 기본 모드는 핵심 파라미터만, "고급" 토글 시 세부 파라미터 노출.

### 3.2 파라미터 목록 (초안)

**① 동력 — 폐·횡격막**

| ID | 이름 | 신체 요소 | 소리 변화 | 범위 (기본) | A | B |
|---|---|---|---|---|---|---|
| `loudness` | 성량 | 폐에서 미는 공기 압력(성문하압) | 음량↑, 고음 배음↑(소리가 밝아짐), F0 약간↑ | 0–100 (50) | ● | ● |
| `breathGroup` | 호흡 단위 | 한 번 숨 쉬고 말하는 길이 | 쉼 위치·빈도 | 짧음–김 | ● | ● |

**② 음원 — 후두·성대**

| ID | 이름 | 신체 요소 | 소리 변화 | 범위 (기본) | A | B |
|---|---|---|---|---|---|---|
| `f0` | 기본 음높이 | 성대 길이·두께·긴장도 (남 17–25mm, 여 12.5–17.5mm) | 초당 진동 수 = 음높이 | 50–600 Hz, 로그 (120) | ● | ● |
| `f0Range` | 억양 폭 | 말할 때 성대 긴장 조절 폭 | 단조로움 ↔ 생동감 | 0–12 반음 (5) | ● | ● |
| `phonation` | 발성 유형 (Rd) | 성대가 맞닿는 강도 (피열연골 내전) | 눌린 소리 ↔ 보통 ↔ 숨 섞인 소리 | 0.3–2.7 (1.0) | ● | ◐ |
| `breathiness` | 숨소리 | 성대가 완전히 닫히지 않는 틈 | 성대음에 잡음 섞임 | 0–100% (10) | ● | ● |
| `jitter` | 주기 흔들림 | 성대 점막 상태·좌우 비대칭 | 거칠고 쉰 느낌 (정상 < 1%) | 0–5% (0.5) | ● | ● |
| `shimmer` | 세기 흔들림 | 성대 진동 진폭 불안정 | 갈라지는 느낌 (정상 < 4%) | 0–20% (2) | ● | ● |
| `creak` | 보컬 프라이 | 성대가 매우 이완되어 불규칙하게 진동 | "드르륵" 긁는 소리, 문장 끝 | 0–100% (0) | ● | ◐ |
| `tremorRate` / `tremorDepth` | 떨림 | 후두 근육의 주기적 수축 | 비브라토, 노인 목소리 떨림 | 0–8 Hz / 0–100 cent (0) | ● | ● |

**③ 필터 — 성도(목구멍·입·코)**

| ID | 이름 | 신체 요소 | 소리 변화 | 범위 (기본) | A | B |
|---|---|---|---|---|---|---|
| `vtl` | 성도 길이 | 성대~입술 길이 (남 ~17cm, 여 ~14.5cm, 아동 ~11cm) | 모든 포먼트가 함께 이동 → 체격감·성별감의 핵심 | 8–20 cm (17) | ● | ● |
| `larynxHeight` | 후두 높이 | 목젖(후두) 위치 | 내리면 어둡고 굵게, 올리면 가볍고 얇게 | −1 ~ +1 (0) | ● | ● |
| `lipShape` | 입술 모양 | 입술 펴기 ↔ 오므리기 | 웃는 목소리(밝음) ↔ 둥근 소리(어두움) | −1 ~ +1 (0) | ● | ● |
| `nasality` | 비음성 | 연구개(목젖 쪽 입천장) 개폐 | 막힌 코(감기) ↔ 정상 ↔ 콧소리 | −1 ~ +1 (0) | ● | ◐ |
| `articulation` | 조음 명확도 | 혀·턱 움직임의 크기 | 웅얼거림 ↔ 또박또박 (모음 공간 크기) | 50–130% (100) | ● | ◐ |
| `ring` | 공명 링 | 후두 위 좁은 공간(후두개 위 공명관) | 2.5–3.5kHz 강조 → 멀리 뻗는 소리 (아나운서·성악) | 0–100% (0) | ● | ● |
| `damping` | 공명 감쇠 | 성도 벽 조직의 부드러움·긴장 | 먹먹함 ↔ 울림 | 50–200% (100) | ● | ◐ |
| `F1..F4 offset` *(고급)* | 개별 포먼트 | 개인마다 다른 성도 모양 | 개인 고유 음색 | ±20% (0) | ● | ◐ |

**④ 조음·말투 — 혀·입술·습관**

| ID | 이름 | 신체 요소 | 소리 변화 | 범위 (기본) | A | B |
|---|---|---|---|---|---|---|
| `rate` | 말 속도 | 조음 기관 움직임 속도 | 빠름/느림 | 2–9 음절/초 (5) | ● | ● |
| `intonation` | 억양 패턴 | 말하는 습관 | 평서/의문/감탄, 문장 끝 처짐 정도 | 프리셋 | ● | ◐ |
| `consonantForce` | 자음 세기 | 혀·입술 폐쇄 압력, 성대 진동 시작 시점(VOT) | 한국어 평음/경음/격음 대비 강도 | 0–150% (100) | ● | ✕ |
| `sibilance` | 치찰음 | 혀끝·앞니 위치 | ㅅ/ㅆ의 날카로움, 혀 짧은 소리 | 주파수 3–9kHz, 세기 | ● | ◐ |

● 지원 / ◐ 근사 지원 / ✕ 미지원

**⑤ 전달 환경 (선택, "목소리 자체가 아님"을 보여주는 대조군)**
- 방 울림, 전화기 필터, 마이크 거리. → "같은 목소리도 환경에 따라 다르게 들린다"를 체험시키는 용도.

### 3.3 매크로(상위 개념) 슬라이더 — 핵심 교육 장치
일반인이 생각하는 "나이·성별·체격·감정"은 사실 여러 저수준 파라미터의 조합이다. 매크로를 움직이면 **어떤 하위 파라미터가 얼마나 움직였는지 화살표로 표시**한다.

| 매크로 | 움직이는 하위 파라미터 (예시) |
|---|---|
| 나이 (아동↔노년) | f0, vtl, jitter, shimmer, tremor, breathiness, rate |
| 남성적↔여성적 | f0, vtl, breathiness, f0Range, larynxHeight |
| 체격 (작음↔큼) | vtl, f0, loudness |
| 감정 (차분/기쁨/화남/슬픔) | f0, f0Range, rate, phonation, loudness |
| 피로·건강 상태 | jitter, shimmer, breathiness, creak |

→ 예: "여성 목소리는 높은 음만이 아니다: 음높이만 올리면 '목소리 높은 남자'처럼 들리고, 성도 길이를 같이 줄여야 여성처럼 들린다"를 직접 체험.

### 3.4 프리셋
성인 남/여, 아동, 노인, 아나운서, 속삭임, 쉰 목소리(흡연자), 감기 걸린 코맹맹이, 저음 성우, 만화 캐릭터 등. 두 프리셋 사이 **모핑 슬라이더**와 **무작위 목소리 생성**도 제공.

## 4. 시각화 설계

### 4.1 해부도 (파라미터 연결 그림)
- **머리·목 단면도 (시상면) SVG**: 폐·기관 / 후두·성대 / 인두 / 연구개 / 혀 / 입술 / 비강을 각각 독립 레이어로 구성.
- **동작 방식**
  - 파라미터 클릭 → 해당 부위 하이라이트 + 상세 패널 열림.
  - 해부도 부위 클릭 → 그 부위에 연결된 파라미터들이 하이라이트 (양방향).
  - **값에 따라 그림이 변함**: `vtl` 이면 성도가 늘어나고, `nasality` 면 연구개가 내려가며, `larynxHeight` 면 후두가 위아래로, `lipShape` 면 입술 모양이 바뀜.
- **보조 그림**
  - 성대 위에서 본 그림(후두경 시점): 진동 속도(F0), 닫힘 정도(phonation·breathiness), 비대칭(jitter)을 애니메이션.
  - 성대 펄스 파형: Rd 값에 따른 펄스 모양 변화.
- 그림은 **단순 의학 도식 스타일 SVG**로 직접 제작 (외부 이미지 불필요, 파라미터로 변형 가능해야 하므로).

### 4.2 음향 시각화 (실시간)
1. **음원 × 필터 = 결과** 3단 스펙트럼: 성대 배음 / 성도 공명 곡선 / 최종 스펙트럼. (가장 중요)
2. 스펙트로그램 + 포먼트 궤적: 단어 재생 시 시간에 따른 변화.
3. 모음 사각도 (F1–F2 평면): 한국어 표준 모음 위치 + 현재 목소리의 모음 위치. `vtl`·`articulation` 변화가 바로 보임.
4. 파형 (확대 시 성대 주기 단위로 jitter/shimmer 확인 가능).

### 4.3 설명 카드 형식 (예시: 성도 길이)
```
[성도 길이]  17.0 cm                           [그림: 단면도, 성대~입술 구간 강조]
 🫁 신체   성대부터 입술까지의 관 길이. 키·목 길이와 관련, 사춘기 남성은 후두가 내려가며 길어짐.
 🔊 음향   관이 길수록 공명 주파수(포먼트)가 모두 낮아짐. 대략 F1 ≈ c/4L.
 👂 느낌   길면 크고 굵은 사람, 짧으면 작고 어린 사람처럼 들림.
 💡 예시   헬륨 가스를 마시면 성도 길이는 같지만 음속이 빨라져 같은 효과가 남.
 ▶ 들어보기: [11cm] [14.5cm] [17cm] [20cm]   (해당 값만 바꾼 소리 비교)
```

## 5. 텍스트 → 음성 처리 (엔진 A)

```
텍스트 → 정규화(숫자·기호→한글) → 한글 자모 분해 → 음운 규칙(연음, 비음화, 유음화,
경음화, 격음화, 구개음화) → 음소열 → 길이 모델(rate) → 운율 모델(f0, f0Range, intonation)
→ 음소별 목표값 테이블(포먼트, 유성/무성, 마찰 잡음, 파열) → 5ms 프레임 궤적(동시조음 보간)
→ 파라미터 적용(vtl·nasality 등) → Klatt 합성 → 오디오
```
- 입력 언어: **한국어 우선**. 한글 유니코드 분해는 공식으로 처리 가능, 음운 규칙은 핵심 규칙부터 단계적으로.
- 한국어 특유의 **평음/경음/격음 (ㄱ/ㄲ/ㅋ)** 은 성대 진동 시작 시점(VOT)과 기식음으로 구현 → 이것 자체도 좋은 학습 소재.
- 한계: 규칙 기반이라 모음은 비교적 잘 나오지만 자음은 근사적. 그래서 실시간 **"지속 모음 모드"**(ㅏ·ㅣ·ㅜ 등을 계속 내며 슬라이더 조절)를 별도로 둔다.

## 6. 엔진 B 변형 방식 (WORLD 보코더)

| 파라미터 | 변형 방법 |
|---|---|
| f0, f0Range | F0 궤적을 로그 영역에서 평균 이동·폭 확대 |
| jitter, tremor, creak | F0 궤적에 무작위 흔들림 / 사인 변조 / 저F0 불규칙 구간 삽입 |
| vtl, larynxHeight, lipShape, F-offset | 스펙트럼 포락의 주파수 축 워핑 |
| nasality, ring, damping | 스펙트럼 포락에 극점/영점 추가, 대역 강조, 켑스트럼 평활 조절 |
| breathiness, phonation | 비주기성(aperiodicity) 증가, 스펙트럼 기울기 조절 |
| shimmer, loudness | 프레임 진폭 변조/스케일 |
| rate | 프레임 시간 축 늘이기/줄이기 |

- 기본 화자 음성을 **2개(남/여)** 준비하고, 목표 값에 더 가까운 쪽을 골라 변형 → 극단적 워핑으로 인한 왜곡 최소화.
- TTS 후보: MeloTTS(한국어 지원, CPU 동작) 등. 라이선스·품질·속도는 P3 시작 시 검증 후 확정.


## 12. 공유·배포 시 엔진 동작

| 구성 요소 | 어디서 실행되나 | 공유 시 비용 |
|---|---|---|
| 화면 + 엔진 A | **방문자 각자의 브라우저** | 없음 (정적 파일만 전달) |
| 엔진 B (TTS + WORLD) | **서버를 연 사람의 PC(GPU)** | 모든 방문자의 요청이 호스트 GPU 하나에 몰림 |

### 공유 방식
1. **같은 와이파이/사내망**: 서버를 `0.0.0.0` 으로 열면 `http://<내 PC IP>:포트` 로 접속 가능.
2. **인터넷 공유 (내 PC 그대로)**: Cloudflare Tunnel / Tailscale Funnel / ngrok 같은 터널로 외부 주소 발급. 공유기 포트 개방 불필요.
3. **상시 운영**: 화면은 GitHub Pages 같은 정적 호스팅, 엔진 B는 클라우드 GPU 서버. (비용 발생, 필요할 때 검토)

### 이를 위해 처음부터 넣는 설계
- **엔진 B는 선택 기능**: 화면이 시작할 때 `/api/health` 확인 → 서버가 없거나 꺼져 있으면 엔진 B 버튼만 비활성화, 엔진 A는 그대로 동작.
- **서버 주소 설정 가능**: 화면과 서버가 다른 곳에 있어도 동작 (`VITE_ENGINE_B_URL`).
- **단일 작업 큐**: GPU 1개로 요청을 순서대로 처리, 대기 순번을 화면에 표시.
- **결과 캐시**: (텍스트 + 파라미터) 해시 → wav 저장, 같은 요청은 즉시 응답.
- **남용 방지**: 입력 길이 제한(예: 50자), IP당 요청 빈도 제한, 공개 모드 시 간단한 접속 키.
- **라이선스 확인**: 공개 공유 시 TTS 모델 라이선스(비상업 조건 등) 준수 — P3에서 모델 선택 시 확인.
